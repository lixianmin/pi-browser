## Review Focus

以下是 spec 隐含、但没有任何任务的测试覆盖到的失败模式。每条都必须在其归属任务的测试里钉住（已就近写进下面对应任务的步骤）。

1. **`spill` 的路径是浏览器虚拟路径。** 上游契约下 `ShellExecResult.spillPath` 指真实临时文件；本仓按 D2 指向 `/tmp` 挂载里的虚拟路径。用**另一个 env 实例**或另一个 `dbName` 去读它必然是 `not_found`——这一步要有测试钉住「同一个 env 读得到、另一个 env 读不到」，否则使用者会以为拿到的是宿主真实路径。
2. **`onOutput` 是 raw、unbounded、unthrottled。** 宿主不自己限流时，一个 `yes` 会把页面打死。测试只断言收到分片，不覆盖背压——要有一条「调用方在 `onOutput` 里中断（abort）后 exec 及时收尾且不继续灌」的测试。
3. **`FileSystem.id` 相同不等于路径空间相同。** 同 `dbName` 的两个实例 id 相同但 `cwd` 可以不同（上游语义：equal ids see the same files at the same paths, whatever their `cwd`）。要有测试钉住「同 id 不同 cwd → 同一世界、`cwd` 是各自视图」，避免被当成「同一个 fs 对象」缓存。
4. **`truncateTail` 的单行超限分支。** 单行比 `maxBytes` 还长时（例如一行 base64），上游会从**尾部**取部分行并置 `lastLinePartial = true`。这一分支的 `outputBytes` / `lastLinePartial` / 内容三者要一起断言，只断言 `truncated` 会漏掉它。
5. **`cleanup()` 之后再 `exec`。** 上游契约只规定 `cleanup` 是 best-effort、不抛，没说 cleanup 后可复用。本仓 worker 已杀、会话已失效——必须**响亮失败**而不是静默挂住。要有测试钉住「cleanup 后 exec 返回错误而非 hang」。

**Files:**

- Test: `test/memory-backend.test.ts`、`test/idb-backend.test.ts`、`test/mount.test.ts`

**Interfaces:**
- Produces（三个后端都实现，签名逐字取自 `pi-durable@1.0.0 dist/env/index.d.ts`）：
  ```ts
  readonly id: string;
  truncateFile(path: string, size: number, context: Context): Promise<Result<void, FileError>>;
  flushFile(path: string, context: Context): Promise<Result<void, FileError>>;
  ```
- Consumes: 无

**语义决定（写进代码注释）：**
- `id`：IDB 后端 = `dbName`（同库 ⇒ 同世界，与 `resetFsKernelRegistry` 的注册表语义对齐）；memory 后端 = 每内核实例一个独立 id。
- `truncateFile`：lightning-fs 没有 truncate 原语时用读–改–写实现；`size` 大于当前长度时按上游注释的 "extend" 语义补零到尾。
- `flushFile`：lightning-fs 没有 per-file flush。如实实现为「触发内核整体落盘」（与 `BrowserFileSystem.flush()` 同一条路径），注释写明这是**能力降级而非等价**。

function methodNames(target: object): string[] {
