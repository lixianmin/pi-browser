> **接续** `2026-10-04-pi-1.0.2-upgrade.md`（只换版本 + 重抄名单）；本 plan 只覆盖 1.0.3 / 1.2.0 真正新增的 3 个 FileSystem 方法 + BinaryReader.scanLines + Shell.exec 形态。`bun.lock` 不动（已是 1.2.0）。

**Goal:** `bunx tsc --noEmit` 0 错（主包 + debugger）；`bunx vitest run` 主包 / debugger 全绿；`idb-backend.test.ts` 与 `memory-backend.test.ts` 的 1.0.3 新增契约块（4 条 / 4 条）跑绿。

**Spec:** `2026-10-02-pi-1.0.0-migration-design.md` §10.1（增量漂移表）、§10.2（P7 实施范围）、§11（决策记录）。

## 实测漂移（1.0.0/2 → 1.2.0，逐符号 cmp 上游产物）

| 符号 | 1.0.2 现状 | 1.2.0 现状 | 本仓动作 |
|---|---|---|---|
| `FileSystem.openBinaryReader` | — | `(path, { noFollow? }, ctx) => Promise<Result<BinaryReader, FileError>>`（必填） | 两个后端 + pull-readers 实现 |
| `FileSystem.openDirReader` | — | `(path, ctx) => Promise<Result<DirReader, FileError>>`（必填） | 两个后端 + pull-readers 实现 |
| `FileSystem.watch` | — | `(targets, onChange, ctx) => Promise<Result<FileWatcher, FileError>>`（必填） | 两个后端答 `not_supported`；host-commands 同步收形参 |
| `BinaryReader.scanLines` | — | `(options, ctx) => Promise<Result<LineScan, FileError>>`（必填） | pull-readers 用上游 `LineScanner` |
| `Shell.exec.command` | `string` | `string \| readonly string[]` | argv 早返 `unknown` 错 |
| `ShellExecOptions.onOutput` 第 3 参 | — | `info: ShellOutputInfo` | 调用点已有 3 参（line 115 / 130），1.2.0 上线即过 |

未变（逐字 cmp）：`FileSystem` 其余 19 个方法（`id` / `readTextFile` / `writeFile` / `truncateFile` / `flushFile` / 等）的形参列表、`Result` / `FileError` / `FileInfo` / `FileKind` / `FileErrorCode`、`Shell` 自身。`watch` 三条新行为（1.0.4）、`ShellOutputWindow` / `ShellOutputSkip`、`ListFilesOptions` 列为非目标（见 spec §10.2）。

## 任务

按依赖序，每步验收后再下一步。

1. **「重装依赖」先于一切**。`rm -rf node_modules && bun install`——把 `@earendil-works/pi-durable` 软链从 1.0.2 切到 1.2.0；`bun.lock` 已是 1.2.0 不动。验收：`node_modules/@earendil-works/pi-durable/package.json` 的 `version` 是 `1.2.0`；`ls node_modules/.bun/@earendil-works+pi-durable@1.0.2*` 还在但不再是 symlink 目标。
2. **`src/env/pull-readers.ts`**：4 个方法（`info` / `read` / `scanLines` / `close`）的 `BinaryReader` 接口 + `DirReader.next` 全部接收 `context` 形参（仅声明，不消费——浏览器后端无异步 IO 可中断）。`scanLines` 实装：`new LineScanner(startLine, endLine); scanner.push(bytes); return scanner.finish()`（上游 `LineScanner` 已 export，自 `pi-durable/env`）。形参校验（`Number.isSafeInteger` + `startLine >= 0` + `endLine > startLine`）保留，非法返 `invalid`。
3. **`src/env/backend-idb.ts`**：
   - `wrap` 增 `context` 形参，方法实现不消费。
   - `openBinaryReader(path, options, context)`：目录走 `statInfo` 判 `is_directory`、缺失 `not_found`；`options?.noFollow` 无视（lightning-fs 无 symlink，但**保留** options 形参为 1.2.0 形参列表完整）；bytes = `f.promises.readFile(abs)`；返 `createBinaryReader(bytes, opened, abs)`。
   - `openDirReader(path, context)`：复用既有 `listEntries(abs)`，返 `createDirReader(snapshot, abs)`。
   - `watch(targets, onChange, context)`：返 `err(new FileError('not_supported', '浏览器 fs 不支持 watch: ' + targets.map(t => t.path).join(', ')))`。
4. **`src/env/backend-memory.ts`**：同 §3，内存版用 `bytesOf(n)` 替代 `f.promises.readFile`。`watch` 同答 `not_supported`。
5. **`src/env/host-commands.ts`** 的 `inlineUnsupportedFileSystem`：每个方法形参按 1.2.0 列表收（`_path, _options, _context` 用 `_` 前缀避免 lint），依旧恒抛 `fail(op)`。无运行时改动。
6. **`src/shell/exec.ts`**：
   - `exec(command: string | readonly string[], options, context)`：`Array.isArray(command)` 即 `err(new ExecutionError('unknown', 'argv form not supported by wasi-sh backend'))`。
   - `onOutput(text, context, { stream: 'stdout' })` 已在 line 115 / 130；1.2.0 形参上线后 `tsc` 即过，不动。
7. **`src/env/mount.ts`**：已是 1.2.0 形参形状（`delegate` 全透传 `context`），不动作；`tsc` 跑通为验收。
8. **测试**：`test/idb-backend.test.ts` 与 `test/memory-backend.test.ts` 1.0.3 契约块（4 条 / 4 条）现成可跑；先在 main 上 `bunx vitest run test/idb-backend.test.ts test/memory-backend.test.ts` 确认**当前 1.0.0/2**下挂的 `openBinaryReader` 报错已消、跑绿；不通过则回 §3 §4 排查。

## 不做的事

- 不实现 1.0.4 `NodeExecutionEnv.watch()` 的「permission_denied / 目录替换 / recursive 覆盖」三条新行为（本仓 `watch` 恒答 `not_supported`，没有这些 case）。
- 不实现 `Shell.exec` argv 形式（wasi-sh / busybox 不透出 argv；早返 `unknown` 错）。
- 不实现 `ShellExecOptions.window` / `ShellOutputSkip`（本仓无输出窗口概念；恒不报 `skipped`）。
- 不实现 `FileSystem.listFiles`（1.2.0 标为 optional；本仓不实现也不造 stub）。
- 不改 `package.json` / `bun.lock` 版本号（已是 1.2.0）。
- 不改 `docs/research/pi-1.0.0/**` 与既有的 1.0.0 / 1.0.2 历史快照。
- 不动 `src/extensions/*` / `src/tools/*` / `src/skills/*` / `src/compaction/*`（它们在 22b6fb0 / F20 阶段已迁完）。

## 风险

- **R1** `LineScanner` 内部状态。`pi-durable@1.2.0` 导出 `LineScanner`（已用 grep 验过），但其 push/finish 的具体边界（是否容忍多字节字符跨 chunk 切分、是否对 BOM 计数）按上游契约行（`start` / `end` / `selectedBytes` / `firstLineBytes` 是解码后字节长度而非字节偏移）。`pull-readers.ts` 的 `scanLines` 测试在主包跑通为准——若上游字段语义与本批「整份读入」实现有出入，对照行字节值会与 1.0.3 契约块第 2 条断言不对齐，需在测试期望上诚实标出。
- **R2** `openBinaryReader` 的 `noFollow` 不实装。本仓浏览器后端无 symlink（`normalizePath` 已在 `..` 边界归一化），缺省/未给与 `noFollow: true` 走同一条路径。注释写明这是能力等价而非 1:1。
- **R3** `inlineUnsupportedFileSystem` 形参加 `_` 前缀可能触发现有 lint 规则对未使用形参的告警。`tsconfig` 当前未开 `noUnusedParameters`（`grep noUnused` 验过），若有 lint 单独管，跑 `bunx tsc --noEmit` 跑通为准。
