日期：2026-10-02
状态：设计已批准（2026-10-02 对话）；本文档待书面评审
上游：`@earendil-works/pi-agent-core@1.0.0` / `pi-ai@1.0.0` / `pi-durable@1.0.0` / `chord@1.0.0` / `pi-coding-agent@1.0.0`（均 2026-10-01 发布）

## 0. 结论速览

- 上游 1.0.0 把 harness 从 `packages/agent` 搬进了 `packages/coding-agent/core`，并把通用 env 原语拆到新包 `packages/durable`。`pi-agent-core@1.0.0` 只剩 agent loop（26 个文件，`exports` 只有 `.`）。**本仓赖以立足的 `harness/**` 从依赖里消失了**——实测 `tsc --noEmit` 报 633 个错，根因是 ~35 个符号没有出处。
- 因此「升级到 1.0.0」的实质是：**把形状真源从 `pi-agent-core/harness` 换成 `pi-coding-agent/core`**。这与本仓既有口径一致——S6 已经把扩展面 1:1 对齐 `pi-coding-agent`，工具名也已经 1:1 对齐 `pi-coding-agent core/tools/`。
- 对齐的是**契约面**（名字、公开签名、类型形状、schema、prompt 文案、名字集合），**不对齐实现体**。上游 1.0.0 的工具/skills/session 实现全是 Node 绑定（`core/tools/*.js` 逐个 import `node:fs` / `child_process` / `node:readline` / `node:crypto` / `node:os`；grep/find 直接 spawn ripgrep + git），浏览器无法复用。本仓继续自持实现体（现状如此）。
- 好消息：**扩展契约零漂移**。逐字比对证实 `ExtensionAPI`（`on` + 31 成员）、`ExtensionAPI.on`（41 个事件名）、`ExtensionContext`（18 成员）在 0.99.1 与 1.0.0 之间**完全相等**（见 F4、F5）。`src/extensions/contract.ts` 与 `test/extensions-contract.test.ts` 不用改。
- 好消息：`AgentTool` / `AgentToolResult` / `FileErrorCode` / `ExecutionErrorCode` 逐字相等（见 F6、F7）。
- 结构好消息：1.0.0 的 `ExtensionRunner` **不再挂 `AgentHarness`/`AgentLane`**，改成注入式（`createExtensionRuntime()` + `bindCore(actions, contextActions)`，每个 Context 成员由一个注入回调兑现）。这消掉了本仓的「context 反演」难题，也干掉了对已消失符号的依赖。
- 实测漂移集中在三处：`FileSystem` 新增 3 个方法、Shell 执行契约换形（`capture`/`onUpdate` → `onOutput`/`spill`）、工具 schema 与 details 形状（`ls`/`find`/`grep` 字段真的不一样）。逐条见 §3.3。
- 交付：一份总 spec + 分阶段 plan（本 spec §3.5 的 P1–P6）。每阶段独立提交、独立跑绿。

## 1. 背景与目标

`pi-browser` 是「浏览器等价的 pi coding agent **能力层**（纯库，无 UI、无产品语义）」，Spice 是第一个消费者。它此前把运行时底座建在 `@earendil-works/pi-agent-core@0.99.1` 的 `harness/**` 上：`ExecutionEnv` / `FileSystem` / `Result` / `FileError` / `Shell*` / `Context` / `AgentHarness` / `AgentLane` / `HookMap` / `HarnessEvent` / `JsonlSessionRepo` / skills / compaction。

2026-10-01 上游发布 1.0.0，把这一层从 `packages/agent` 移走并重构。本仓随之从 0.99.1 升到 1.0.0。

**目标**

1. `pi-agent-core` / `pi-ai` 升到 1.0.0，`tsc --noEmit` 0 错，既有 338（主包）+ 30（debugger）测试全绿。
2. 凡属「`pi-coding-agent` 契约面」的形状，逐字对齐 1.0.0（沿用 S6 §1 的用户口径：**接口级一模一样，不造「差不多」的名字**）。
3. 浏览器兑现不了的地方**保留原名、明确列不支持**，并在 README 与本文档「平台偏差」节如实声明——不发明旁路。

**非目标**：见 §7。

## 3. 设计

### 3.1 1:1 的边界（全 spec 的判据）

**对齐**：名字、公开签名、类型形状、schema 字段与字段名、prompt 文案（`description` / `promptSnippet` / `promptGuidelines`）、封闭名字集合（成员名 / 事件名）。

**不对齐**：实现体。判据是「上游实现是否可在浏览器运行」——实测全部不可（F12 的工具体 import `node:fs`/`child_process`；F10 的 `OutputAccumulator` import `node:crypto`/`node:os`；F14 的 `loadSkills` 同步读 node fs）。本仓自持实现体，只把形状钉到上游。

**平台偏差**必须逐条登记（§3.4），并在 README 如实声明——这是 S6 §1「浏览器跑不到的成员保留原名、明确列不支持」口径的延伸。

### 3.2 依赖与分层

```
runtime deps（浏览器安全，F3 已核实）
  ├─ @earendil-works/pi-agent-core@1.0.0   agent loop / AgentTool / ThinkingLevel（零漂移面）
  ├─ @earendil-works/pi-ai@1.0.0           Model 类型（上游新增 ./models 子路径，本仓用不到）
  ├─ @earendil-works/pi-durable@1.0.0      /env + /env/node：FileSystem / ExecutionEnv / Result / FileError / Shell*
  └─ @earendil-works/chord@1.0.0           /context：Context / BACKGROUND_CONTEXT

devDep
  └─ @earendil-works/pi-coding-agent@1.0.0 形状真源：契约对照测试 + Node 等价测试直接读上游产物
```

`pi-coding-agent` 只能作 devDep（F2 的 Node CLI 依赖树）。它是**形状真源**：契约测试与等价测试直接 import 上游产物，不再只靠人工对抄。人工对抄表（`src/extensions/contract.ts`）保留——它是双确认机制的一半（S6 §4 的护栏），devDep 让它从「唯一证据」变成「可自动复核的证据」。

分层不变：`src/index.ts` 是唯一公开面，消费者禁 deep import。

### 3.4 平台偏差表（浏览器做不到 1:1 的地方）

每条都必须在 README「平台偏差」节如实声明。

**D1 `Buffer` → `Uint8Array`。** 上游 `ReadOperations.readFile: (absolutePath) => Promise<Buffer>`、`BashOperations.exec` 的 `onData: (data: Buffer) => void`、`OutputAccumulator.append(data: Buffer)` 都带 Node 全局 `Buffer`。`Buffer` 是 `Uint8Array` 的子类，改用 `Uint8Array` 语义无损（只按字节用，不做 Buffer 独有操作）。不引入 `buffer` polyfill：为一个类型名新增运行时依赖 + 放大 bundle 不值。凡与上游同名处，类型签名逐字照抄、只把 `Buffer` 换 `Uint8Array`，并在声明处写一行注释说明。

**D2 临时文件落挂载表。** `OutputAccumulator` 的 spill 走 `node:os.tmpdir()` + `node:fs.createWriteStream`。浏览器路径改为经挂载表里的 `/tmp`（`createBrowserExecutionEnv` 默认挂载 `/tmp`→内存）写文件；`OutputSnapshot.fullOutputPath` 因此是**浏览器虚拟路径**（如 `/tmp/pi-bash-xxx`），不是宿主真实路径。注释与 README 都要说清。

**D3 `loadSkills` 保持异步。** 上游 1.0.0 是同步函数（Node fs）。浏览器后端的读是 Promise（IDB / lightning-fs），无法同步。名字与选项形状照抄，返回值变成 `Promise<LoadSkillsResult>`。这是本仓既有行为（`loadBrowserSkills` / `loadSkillsFromEnv` 已是异步），迁移只是改名与补字段。

**D4 `ExtensionRunner` 构造收窄为 `(extensions, runtime, cwd)`。** 上游是 `(extensions, runtime, cwd, sessionManager, modelRegistry)`；实测 `sessionManager` 写 1 次读 0 次（F17），`modelRegistry` 只服务本仓已判「不支持」的 provider / 虚拟模型面。按「不发明形状」的口径，不收这两个参数，也不造 stub。`getModelRegistry()` 随之不实现（它只服务不支持面）。

**D5 工具的 `operations` 缺省即抛错。** 上游 `options.operations?` 可省，缺省走本地文件系统；浏览器没有「本地文件系统」。类型上仍保持可选（保 1:1 签名形状），运行期缺省时**响亮抛错**并给出指引（照 AGENTS §「静默失效比报错更糟」）。不新增自造的「便捷包装」名（S6 §3.1 禁止造差不多名字）。

**D6 图片读取的实现面。** 上游 `read` 支持图片（`ReadOperations.detectImageMimeType?` + `ModelImageResizeOptions` 自动缩放，缩放用 `@silvia-odwyer/photon-node` wasm）。浏览器侧：magic-byte 嗅探可用（无 node 依赖），自动缩放需要 canvas/offscreen canvas。**待裁决**——见 §8 R1。

**D7 浏览器没有的 shell 能力照旧声明。** `spawnHook` / `shellPath` / `exposeSessionEnvironment`（生成 `PI_*` 环境变量）在浏览器侧无对应物；沿用 S2 已建立的「如实声明」口径，不声明不生效的字段。

## 8. 风险与待裁决

**R1（待裁决）`read` 的图片支持。** 上游 1.0.0 的 read 支持 jpg/png/gif/webp/bmp，走 `ReadOperations.detectImageMimeType` + 自动缩放（`photon-node` wasm）。本仓现状是纯文本。三个选项：
- (a) 跟上游：加 magic-byte 嗅探返回 `ImageContent`，自动缩放先不做（声明 `autoResizeImages` 不支持，超限图片如实报错）—— 形状 1:1，实现最小。
- (b) 跟上游且做缩放：加 canvas/offscreen-canvas 缩放。实现量最大，且引入「浏览器有没有 OffscreenCanvas」的平台分支。
- (c) 不跟：read 明确声明「仅文本」，把差异写进 README 的「不支持」节。
**建议 (a)**：形状对齐、能力如实声明、不引入新分支。

**R2（待裁决）是否引入 `pi-durable/testing` 的 storage-conformance 做通用一致性对照。** 好处：多一层自动化护栏。代价：`pi-durable` 的 `Storage` 是它自己的 durable 模型（`Harness` / `AgentDoc` / `LiveDoc`），与本仓的「单写者 fs + session JSONL」不是同一个抽象——硬套会造出「差不多」的对照。**建议不引入，只做 P5 的 `SessionManager` 往返对照。**

**R3（待裁决）`loadBrowserSkills` / `loadSkillsFromEnv` 两个本仓自造名的去向。** 它们不属于上游名字表（上游是 `loadSkills` / `loadSkillsFromDir`）。按 S6 §3.1「不造差不多的名字」，应删掉、只留上游名；但二者是既有公开面 API（README 与 `public-surface.test.ts` 都锁着），删是破坏性变更。**建议删，只留 `loadSkills`（异步，D3）**，在 README 写明这是 1.0.0 迁移的破坏性变更。

**R4 上游 1.0.0 是「昨天」发布的（2026-10-01）。** `pi-durable` 的 README 自己写着「**Experimental.** The API changes without notice between releases.」`pi-durable/env` 是本批唯一新增的运行时依赖，且是 env 契约的唯一来源。若它在下个版本再次搬家，本仓要再动一次 P1。缓解：env 契约在本仓有完整对照测试（方法集合 + 策展等价表），漂移会立刻红。

**R5 `id` 语义是新增的（F3、C3）。** 本仓此前没有「文件命名空间 id」概念，`dbName` → `id` 的映射是本批新造的语义。若上游对 `id` 的用法超出「相等即同世界」，映射要重估。

**R6 事件路由要重写。** `AgentHarness` 的 `hooks` / `events` 是本仓 25 条事件路由的落点（S6 §3.4）。落点消失后，路由目标要改成 runner 自己的 emit 入口，且宿主（消费者）要负责在对的时机调它们。这是 P3 里最容易出「看起来对但其实没接上」的地方——每条路由都要有触发测试（不能只测注册）。

**R7 `sessionManager` 上游写而不读（F17）是「此刻」的实测结论。** 若上游下个版本开始读它，D4 的收窄就要重估。缓解：devDep 对照测试不覆盖构造参数，这一点靠人复查；在本 spec 留下 F17 的出处，下次升级时重跑同一条 grep。
